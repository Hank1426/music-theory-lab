## Context

仓库 `music-theory-lab` 目前只有 OpenSpec 脚手架，没有应用代码。本 change 是项目的第一个 change，从零建立简洁版识谱练习应用，功能对齐参考产品「口袋五线谱」的单音练习（截图与录屏分析见 `参考界面/`），但不复用其任何代码、素材或视觉资产。

开发环境约束：电脑上只有 Node v24 和 Python，没有 JDK / Android SDK / Flutter。用户手机为国产安卓（小米系系统浏览器，无 Chrome、无 GMS）。

已确认的行为（来自参考产品录屏）：

- 默认模式 = 该组每个音各考一次，随机顺序；题号 `N/总数`；正计时。
- 点错：停在原题等重试，这题记为错；按下任意键时播放该键的音（点错也播放）。
- 点对：绿色提示条；点错：红色提示条；按下的琴键变蓝色（只表示按下，不表示对错）。
- 第一题点对才计对，点错过（含用提示）仍算错。
- 最后一题点对后立即进入结果页：正确率、星级、正确/错误数、用时（秒，3 位小数）、错题集（记录误选的键）。
- 谱面：整行显示，4/4 拍，随机四分/二分/全音符凑满小节，最后一小节可不满，只考音高；每行 2 小节。
- 键盘音名用中文记法带上标组号（c¹…b¹），结果页同记法。

## Goals / Non-Goals

**Goals:**

- 手机浏览器可用的单音练习闭环：选组 → 练习 → 结果 → 历史。
- 谱面排版完全对齐参考产品（整行、装饰节奏、当前题高亮）。
- 数据模型一次到位：逐题记录（目标音、点过的键、提示、反应时间），为将来的错题本 / RT 统计免迁移。
- 分组用数据表 + 筛选条件描述，加新分组只加数据。
- 竖屏手机上可正常使用（初级各组只需单谱号、加线 ≤5 条、一个八度键盘）。

**Non-Goals:**

- 中级 / 高级 / 「其他音符」分组（跨谱号、8va 记号、滑动键盘）——第 2、3 阶段。
- 限时练习、组合练习、MIDI 输入、错题本、自定义练习、课程、工具、登录、积分、排行榜、广告、社区。
- 后端、账号、云同步。
- 谱面渲染性能优化（超过一屏的长谱）。

## Decisions

### D1 技术栈：Web 单页应用

`Vite + TypeScript（无框架或轻框架）+ VexFlow + Web Audio API + localStorage`

- 为什么：电脑只有 Node；VexFlow 直接解决谱号字形 / 符干方向 / 加线 / 间距 / 分行，这是本应用最大的排版风险；逻辑层可写成纯 TS，将来套 PWA 或 Capacitor 壳不用重写。
- 备选：Kotlin/Compose（音质和延迟最优，但要装数 GB 工具链，谱面要手写 Canvas）；Flutter（同样无现成乐谱库）；微信小程序（要注册账号，VexFlow 要改造）。均被「最小化开发 + 现有工具链」否决。
- 运行方式：开发期局域网 HTTP 访问；正式使用部署 HTTPS 后装成 PWA；若国产手机 PWA 体验差（全屏/离线/手势冲突），用 Capacitor 打 APK，可走 GitHub Actions 云构建，本机仍不需 Android SDK。

### D2 音符目录：数据表 + 筛选条件，而不是每组建模

52 个白键一张表，每行字段：

```
midi（21..108，白键）、国际记法（C2）、中文记法（C / c / c1 / c2…）、
八度组、音区（低/中/高）、谱号（B3 及以下低音、C4 及以上高音）、常用（C2..B6）
```

分组预设 = `{难度 tab, 分类, 组名, 描述, 音符筛选条件, 预计题数}`，如「初级 / 常用音符 / 小字一组 / 筛选:八度组=小字一组 / 7」。

- 为什么：中级「下加线/中间线/上加线」经反推是由谱号和谱表位置**自动可算**的（下加线 15 + 中间线 18 + 上加线 19 = 52），第 2 阶段加分组不需要新代码路径，只是新筛选条件。
- 谱表位置由「音高相对谱表最低线（E4/高音，G2/低音）的字母序号差」纯函数计算，该函数必须有单元测试（参考产品 1.2.1 版修过此 bug）。

### D3 谱面生成：节奏是装饰，音高是题目

- 生成顺序：先按结束方式出题（音高序列），再把序列切成「每行 2 小节」的块，每小节随机选 `[4/4,2/2,1/2,1]`（四分×4、二分×2、全音符）凑满 4 拍，最后一小节可不满。
- 音高与节奏解耦：判定只看音高序列的推进，节奏变化不触发任何逻辑。
- 渲染用 VexFlow：`Voice` 用 `Mode.STRICT` 允许小节不满；加线、符干方向交给库；当前题高亮用音符下方叠加蓝色矩形（参考产品为蓝底块）。
- 为什么不用自绘 SVG：符干位置、符干方向、横向间距、谱号字形都是易错细节，VexFlow 已解决。

### D4 键盘与发声

- 只渲染当前组所在的一个八度（7 白键 + 不参与答题的黑键占位），键上音名可开关（默认开，同参考产品）。
- 出题时不播放目标音（音感好的人不需要练识谱）；`pointerdown` 触发 `WebAudio` 播放按下的采样音，对错同一处理。
- 音频采样：Salamander Grand Piano（CC-BY）白键子集打包进应用；首次用户手势（点「开始」）解锁 AudioContext。
- 判定规则：第一次按下即正确 → 计对；按下错误 → 记录误选键、红色提示条、停在原题；提示 → 高亮正确键、该题计错、等用户点该键后进入下一题。

### D5 存储与会话模型

```
SessionRecord = {
  id, startedAt, durationMs, group, difficulty, mode(默认/数量), totalCount,
  correctCount, hintCount,
  items: [{ targetNote, pressedKeys[], hinted, firstPressCorrect, rtMs }]
}
```

- localStorage key 前缀 `mtl.`；写入时调用 `navigator.storage.persist()`（尽力而为）。
- 累计统计：练习数量 = items 总数（题数）；练习场次 = SessionRecord 数；准确率 = ΣfirstPressCorrect / ΣtotalCount。
- 为什么现在就存逐题明细：将来错题本「误认方向」、RT 分位统计都要用，晚存就要迁移。写视图（如准确率）只是对 SessionRecord 的聚合。

### D6 结果页与星级

- 数据：正确率（正确题数/总题数）、星级（≥95% 5 星 / ≥85% 4 星 / ≥70% 3 星 / ≥50% 2 星 / 其余 1 星）、正确/错误数、用时（毫秒换算为秒，保留 3 位）、错题集列表。
- 错题集条目：`第 N 题：正确答案是 a1，但是选择了 b1`（多个误选键用「、」连接）；用提示的条目标注「（使用了提示）」。
- 「再来一次」重新生成同组练习；不设积分 / 排行榜 / 广告。

## Risks / Trade-offs

- [谱面视觉与参考产品存在偏差（字体、间距、高亮样式）] → 先实现结构对齐（行/小节/音符种类/高亮），视觉细节后续迭代；不接受像素级复刻（也避免视觉抄袭）。
- [浏览器音频延迟影响手感] → M0 先做音频 spike（1 个采样 + 1 个琴键在真机验证）；采样用 44.1kHz 短样本控制解码开销。
- [国产系统浏览器 PWA 行为未知（无 GMS、地址栏、清存储、侧滑手势）] → 开发期用局域网页验证功能；部署后真机做 PWA 检查单（全屏/离线/存储/滑动冲突四项），不通过则走 Capacitor 云构建 APK。
- [VexFlow 输出尺寸在小屏上过小 / 高亮定位复杂] → 用 SVG 后端按容器宽度渲染；高亮矩形从 `StaveNote.getAbsoluteX()`/`getNoteHeadBounds()` 计算，写一个独立适配层并测试。
- [项目根目录无 `package.json`，需从零搭工程] → M0 一次性搭好脚手架 + 测试 + 采样加载，后续任务只填逻辑。
- [localStorage 被浏览器清理导致记录丢失] → 尽力 `persist()`；接受此风险（MVP 无云同步）。

## Migration Plan

新应用，无存量数据需要迁移。分阶段：M0 脚手架与音频 spike → M1 音符目录 + 谱面渲染 → M2 练习闭环 → M3 结果 / 历史 / 统计 → M4 手机真机验收。部署为静态站点，回滚 = 重新部署上一构建产物。

## Open Questions

- 💡 提示的视觉形式（参考产品录屏未展示）：当前定为「高亮正确琴键 + 该题计错」，是否还需要在谱上标记？
- 同一题多次点错，错题集是否列出全部误选键（当前设计：列出全部，用「、」连接）？
- 中级「中音区」的跨谱号排版（同一行切换谱号 vs 上下两行）→ 第 2 阶段补录屏后定。
- 全音区键盘交互（滑动 vs 切八度按钮，参考产品「c」按钮用途未确认）→ 第 2 阶段补录屏后定。
- 星级阈值（当前定 95/85/70/50）是否合适 → 用户试玩后调。
- 「每行显示组数」是否做成设置项（参考产品有，当前 MVP 固定为 2）。
